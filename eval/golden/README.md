# Golden для сценариев жюри · 300 записей

Текущая версия `judging-golden-2`: **280 самостоятельных вводов и 4 диалога по 5 шагов**.
У каждого самостоятельного ввода своя исходная группа: похожие пары и тройки из старого
набора больше не попадают в прогон целиком. Всего 284 группы вместо прежних 102.
CSV не создавался. Исходные семь файлов исследовательского банка сохранены без изменений.

Сценарии основаны на командном пересказе замечаний жюри. Это набор для валидации, без официальных скрытых тестов.
Набор выбран и размечен до запуска продукта: ошибки реализации не служили причиной исключения кейсов.

Примеры разных механизмов ошибок:

- `JUDGE-C03`: «Халат детский, размер 1 литр, материал хлопок.» — странное значение видно с предупреждением.
- `JUDGE-F03`: мягкое сиденье, спинка **без мягкой обивки** — отрицание относится к спинке.
- `JUDGE-F04`: вес в граммах и масса в килограммах — одно свойство кресла; коробка отдельно.
- `JUDGE-F08`: при установленном единственном коде незаполненные обязательные поля дают предупреждение.
- `JUDGE-T04`: X18-2026 — модель; питание 12 В — параметр.
- `LANG-010`: «Стл офисн, шрн 60 см, вст 75 см.» — неоднозначные сокращения нельзя угадывать.
- `NUM-144`: «Молоток -1 кг: не знаю, это минус или тире без пробела.»

## Разметка и границы оценки

У всех 280 вводов размечена категория, исходные полные `must` / `forbidden` и хотя бы
одна автоматическая проверка поведения помимо категории. Всего **328 требуемых фактов,
199 запрещённых выводов и 275 сохраняемых фрагментов**. Факты задают тип, значение,
единицу, оператор, статус, владельца и точную исходную цитату. Это проверяемые опорные
условия, а не полная разметка всех допустимых формулировок. Их составлял один куратор;
независимую экспертизу специалиста КТРУ эта версия не проходила.

Разделены установленный код и полнота карточки. Из перенесённых опорных условий убраны
безусловные `no_final` и `clarification_required`: пропущенное/спорное значение само по себе
не доказывает неоднозначность кода и не требует обязательного пошагового опроса.
При реальной неоднозначности нужен вопрос, различающий активных кандидатов.

В `must` новых кейсов записаны проверки актуальной ACTIVE версии, приоритета КТРУ → Портал → New,
предупреждения о чужом свойстве, возможности исправить/игнорировать, минимальных вопросов
и отображения однозначного кода при незаполненных полях. **Они остаются ручными проверками**:
точные коды/версии и полный набор кандидатов не размечены по зафиксированному каталогу.
`pass_checks` не означает, что эти требования или весь UI прошли проверку.

Диалоги сохранены целиком вместе с настоящими операциями и предусловиями. Недоступная
операция остаётся `fixture_missing`, не превращается в отдельный parse и не считается успехом.
`--with-model` запускает модель только для самостоятельных вводов; диалоги идут с правилами.

## Файлы и запуск

- [cases.jsonl](cases.jsonl) — 300 записей с исходниками и разметкой.
- [selection.json](selection.json) — явные case IDs, группы, состав и правила отбора.
- [manifest.json](manifest.json) — версия, счётчики и SHA-256 всех восьми файлов банка и артефактов.
- [dialogues.json](dialogues.json) — четыре полных плана операций.
- [curation-audit.json](curation-audit.json) — аудит полноты, дубликатов, происхождения и решений.
- [08-judging.tsv](../../research-library/09-user-input-corpus/2026-10-10/cases/08-judging.tsv) — 24 новых исходных ввода.

```bash
uv run --project backend --python 3.12 python eval/run.py golden --validate-only
KTRU_SNAPSHOT_DIR=.ktru-build/snapshots/current \
  uv run --project backend --python 3.12 python eval/run.py golden
```

Отчёты сохраняются в `.ktru-build/eval/` или `$KTRU_BUILD_DIR/eval/`.
Валидатор проверяет исходные строки и хеши, явный выбор, одиночные группы, полные диалоги,
типы значений и наличие цитат в исходнике. Старый Golden и исходный банк скопированы в
`.ktru-build/golden-redesign-20261010/original-golden/` и `original-bank/` перед изменением;
старые отчёты относятся к прежнему составу и несопоставимы с новым прогоном напрямую.

Это открытый синтетический validation-набор. Seed smoke, независимый holdout,
accuracy точного кода, Linux VRAM и приёмочные пороги проверяются отдельно.
`eval/thresholds.yaml` не изменялся. Успех валидации файлов не доказывает качество продукта.
